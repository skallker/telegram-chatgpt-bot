# Telegram × ChatGPT

Учебный Telegram-бот на Python: 4 обязательных режима из ТЗ и 2 дополнительных.
Интерфейс — на русском. Ответы обычного чата и резюме следуют языку пользователя.

## Возможности

| Команда | Поведение |
| --- | --- |
| `/start` | Меню, завершение режима и очистка истории пользователя |
| `/random` | Подготовленная картинка, факт от ChatGPT, ещё факт, завершение |
| `/gpt` | Картинка и чат с историей; поддерживается `/gpt вопрос` |
| `/talk` | Картинка, выбор Эйнштейна, Марии Кюри или Сократа; ролевая беседа |
| `/quiz` | Картинка, 4 темы, вопросы и оценка от ChatGPT, счёт, смена темы |
| `/translate` | Выбор одного из 5 языков, перевод и смена языка |
| `/resume` | Пошаговый сбор должности, образования, опыта и навыков |
| `/help` | Список команд |
| `/cancel` | Возврат в меню с очисткой истории |

Бот работает в личных чатах. Кнопка «Закончить» эквивалентна `/start`.
Счёт квиза сохраняется при смене темы и сбрасывается при новом `/quiz`.
Ролевые ответы обозначены как имитация, а не реальные цитаты.

## Запуск в Windows / PyCharm

Нужен Python 3.11 или новее. Локальные проверки выполнены на Python 3.12.

1. Скачай проект и распакуй папку. Открой её в PyCharm.
2. Открой терминал в корне проекта, где находятся `requirements.txt` и `bot`.
3. Создай окружение и установи зависимости:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если установлен Python 3.13, в первой команде используй `py -3.13`.
Активация окружения не обязательна: команды используют его Python напрямую.
В PyCharm выбери интерпретатор `.venv\Scripts\python.exe`.

4. В Telegram открой официальный `@BotFather`, выполни `/newbot` и создай бота.
5. Открой `.env` в редакторе и заполни:

```dotenv
TELEGRAM_BOT_TOKEN=вставь_токен_от_BotFather
OPENAI_API_KEY=вставь_ключ_OpenAI
OPENAI_MODEL=gpt-4o-mini
ALLOWED_USER_IDS=
```

Ключ OpenAI из учебного файла нужно вставить локально в `OPENAI_API_KEY`.
Он намеренно не включён в проект. Доступность модели и бюджет зависят от ключа.
При необходимости поменяй `OPENAI_MODEL` на доступную совместимую модель.
`ALLOWED_USER_IDS` можно заполнить числовыми Telegram ID через запятую,
чтобы ограничить доступ; пустое значение разрешает всех пользователей.

6. Запусти:

```powershell
.\.venv\Scripts\python.exe -m bot
```

7. Открой своего бота в Telegram и отправь `/start`.
Остановка — `Ctrl+C`. Две копии одного бота одновременно не запускай.

В конфигурации запуска PyCharm укажи **Module name: `bot`** и корневую папку
проекта как Working directory. Не запускай `bot/app.py` напрямую.

## Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# Заполни .env в редакторе.
.venv/bin/python -m bot
```

Для работы 24/7 потребуется постоянно работающий компьютер или сервер
с процессом `python -m bot` и переменными окружения. Само размещение кода
на GitHub не запускает Telegram-бота. Веб-сервер и ngrok не нужны:
используется long polling. Развёртывание на сервере не выполнено.

## Устройство проекта

- `bot/config.py` — чтение настроек и проверка обязательных переменных.
- `bot/ai.py` — запросы OpenAI, тайм-ауты, проверка структуры вопросов и оценок.
- `bot/app.py` — команды, кнопки, ConversationHandler, режимы и история.
- `bot/__main__.py` — запуск и безопасное логирование.
- `assets/` — шесть готовых PNG-заставок, по одной на режим.
- `tests/test_bot.py` — тесты без сети и настоящих ключей.
- `.github/workflows/checks.yml` — проверки для Python 3.11, 3.12, 3.13.

Истории пользователей разделены. Для чата сохраняются последние 6 пар
вопрос/ответ. Данные хранятся только в оперативной памяти, не в базе данных.
После перезапуска сбрасываются режимы, счёт и история; накопившиеся до запуска
сообщения Telegram отбрасываются, чтобы не отправлять старые запросы в API.

ConversationHandler обрабатывает обновления последовательно. Во время
долгого запроса остальные сообщения ожидают; это учебная реализация,
не высоконагруженный публичный сервис. Один API-запрос ограничен 55 секундами,
включая повтор SDK. Длинные ответы разбиваются на Telegram-сообщения.
Тексты не разбираются как Markdown, поэтому символы из ответа не ломают отправку.

При ошибках API счёт и история не обновляются, пользователь может повторить
запрос. Старые кнопки предыдущих режимов отклоняются. Ошибки логируются
по типу без текста запросов, ответов, ключей или URL с Telegram-токеном.
Логи HTTP-клиентов отключены. Не включай DEBUG без дополнительной фильтрации.

Качество фактов, переводов и оценки квиза зависит от модели: структурная
проверка JSON не гарантирует фактическую безошибочность ответа.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
ruff check .
ruff format --check .
python -m unittest discover -s tests -v
```

Тесты проверяют все шесть режимов, изоляцию и ограничение истории, старые
кнопки, повторные ответы, подсчёт баллов, восстановление после ошибок,
смену языка, сбор резюме, ограничения доступа и длинные сообщения с эмодзи.
Настоящие запросы к OpenAI и Telegram в тестах заменены заглушками.
Полный живой запуск требует действующих ключей и отдельной проверки в Telegram.

### Ручная приёмка после настройки ключей

1. `/random`: получить факт, нажать «Хочу ещё факт», затем «Закончить».
2. `/gpt`: задать вопрос и уточнение к нему; убедиться, что контекст сохранён.
3. `/talk`: выбрать личность, задать два вопроса, закончить.
4. `/quiz`: ответить верно и неверно, проверить счёт и сменить тему.
5. `/translate`: выбрать язык, перевести текст, сменить язык.
6. `/resume`: заполнить четыре ответа и получить текст резюме.
7. `/start`: проверить очистку режима; старая кнопка должна быть отклонена.

## Безопасная публикация

В GitHub должны попадать код, картинки, тесты и `.env.example` с пустыми
значениями ключей. `.env` и файлы `*token*.txt` исключены через `.gitignore`.
Не добавляй их принудительно командой `git add -f`.
Если ключ случайно опубликован, отзови его у провайдера: удаления файла
из последнего коммита недостаточно, он может оставаться в истории Git.

## Использованная документация

- [OpenAI Chat API](https://developers.openai.com/api/reference/resources/chat)
- [python-telegram-bot ConversationHandler](https://docs.python-telegram-bot.org/en/v22.5/telegram.ext.conversationhandler.html)

API-интеграция использует Chat Completions для совместимости с моделью
`gpt-4o-mini`, указанной в учебном задании. Секреты, данные пользователя
и исходный файл с общим ключом группы в репозиторий не включены.
